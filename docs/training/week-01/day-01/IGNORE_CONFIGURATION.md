## Purpose of each exclusion

- **`.dart_tool/`** – tooling metadata generated by `flutter pub get`.
- **`build/`** – compiled artifacts that are regenerated on each build.
- **`.pub-cache/` & `.pub/`** – local package caches.
- **`coverage/`** – code‑coverage reports.
- **`pubspec.lock`** – lockfile; we keep it in the repo for reproducibility, but it is **optional** for AI context and is excluded from AI‑only ignore files.
- **`**/_.g.dart`, `\*\*/_.freezed.dart`, `**/\*.mock.dart`** – typical generated Dart files from code‑gen packages (currently none exist in the repo).

## Antigravity compatibility notes

- **Supported**: Antigravity **automatically** respects `.gitignore`. The entries for `.dart_tool/` and `/build/` are already effective.
- **Not supported**: Antigravity does **not** parse `.cursorignore` or `.aiignore`. Those files are kept for compatibility with other tools (e.g., VS Code‑Cursor, custom scripts) but they **will not affect** the AI’s workspace indexing unless the user manually enables a setting that reads them (which is not the case here).

## Why `pubspec.lock` stays in the project

`pubspec.lock` records the exact versions of dependencies and is useful for reproducible builds. It is **not** added to `.gitignore` because many teams version‑control the lockfile. We exclude it only from the AI‑only ignore files to reduce potential token noise, but it remains part of the repository and is still readable by the AI (since Antigravity does not block it).
